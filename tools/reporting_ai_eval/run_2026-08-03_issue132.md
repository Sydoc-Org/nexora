# Run: 2026-08-03, INT, gpt-4o-mini — grounding fixes for #132

Before/after pair for the four grounding gaps in issue #132. Both runs were
collected on the same day, on the same INT data, against a dev server started
from the `feature/reporting-ai-grounding-132` worktree — the only difference
between them is the prompt change in that branch. Each case was judged by an
independent agent against its `good` line in `prompts.json`, reading the full
response *and* the tool trace, with the same rubric text for both runs.

**Do not compare these numbers against `baseline_2026-07-28.md`.** That table
predates the #127/#128/#129 fixes, so it no longer describes the agent this
change was made to. It also predates the calendar moving on: on 2026-08-03
"this month so far" is a 3-day, nearly empty window, which changes several
cases for both runs equally.

**Result: 5.41 → 6.23 average (+0.8).** 11 cases up, 6 unchanged, 5 down.

## Gap by gap

**1. Workitem-count semantics — closed.** Case 16 went 1 → 8, the largest
single move in the run. Before: drafted `COUNT(DISTINCT WorkItem)` across
process tables, hit two SQL errors, burned all 10 turns probing schemas and
returned no number (`stoppedReason: max_turns`). After: unioned all five
partial tables, used `COUNT(*)`, and stated "one row = one workitem in these
tables" — the fact the grounding now carries. It reported July 2026 = 1
without remarking that such a total is thin, which is the remaining point off.

**2. Ambiguity disclosure — behaviour fixed, score unmoved.** Case 17 stayed
at 5, but for a different reason than before. Before it never surfaced the
calendar-vs-rolling ambiguity at all and asked permission to run. After it
opens by naming its reading (calendar Q2 2026) *and* the alternative (rolling
last 3 months) — exactly the required behaviour — then loses the points on an
unrelated SQL failure it never diagnosed. The judge also flagged that it
closed with a list of caveats it then said did not apply: the checklist can
produce padding when nothing on it is warranted.

**3. Mandatory caveats — closed, broadly.** In the before run the judges
recorded `CAVEAT: no` where one was warranted on cases 1, 2, 4, 7, 8, 9, 10,
13 and 16; in the after run every one of those except 16 is `yes`. The clearest
case is 9 (4 → 8): before, a naive mean silently computed over only the months
that had rows, giving 15/month when the true 12-month mean was 6.25, presented
with no uncertainty caveat; after, the zero-fill assumption is named, the
arithmetic reconciles, and the thin baseline is stated.

**4. Not handing the question back — the mixed one.** Three cases that
previously stopped with turns left now do the work: 12 (2 → 8), 13 (3 → 8) and
18 (6 → 8, all three parts delivered from a query it recovered onto after a
failure). But cases 11, 20 and 21 still quit, and the rule did not hold in
cases 5, 10 and 14 — see below.

## The regressions, honestly

Four of the five drops (5, 10, 14, and case 17's stalled score) are the same
failure: a `run_sql` attempt dies on `Invalid column name` because the partial
tables do not share column names, and the agent stops rather than probing
`INFORMATION_SCHEMA` and retrying — which is what the *before* run happened to
do on those cases. That friction is pre-existing and equally present in both
runs: `Invalid column name` appears in cases 5, 14, 16 and 18 before, and 5,
10, 14 and 18 after. What varies run to run is whether the agent recovers from
it, and the new "do not hand the question back" rule did not reliably make it
recover. Case 5 is the sharpest example (9 → 3) and it is also the run's only
score-9 regression.

Two conclusions follow. First, these are single runs of a non-deterministic
agent: individual case deltas of ±3 are within what the agent does on its own,
so the aggregate and the per-gap behaviour flags are the trustworthy signals,
not any one case. Second, the real remaining lever is not prompt text — it is
that per-process column-name discovery is left to trial and error. Giving the
agent the column names it needs up front, or a schema-probe tool it reaches for
before drafting a UNION, would recover more points than any further wording.
