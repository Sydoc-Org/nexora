## How these releases were integrated

Unlike the older releases visible in this repo's history (2.5.10 – 2.5.51,
which were merged via GitHub pull requests producing `Merge pull request
#NN` commits), **none of 2.5.52 – 2.5.55 used a PR merge commit**. They are
linear, fast-forward integrations into `main` — each release branch is just
a label pointing at the snapshot of `main` at the moment the version was
cut. The last PR-style merge in the history is:

- `9fde5d9` — `Merge pull request #80 from Sydoc-Code/2.5.51`

Everything documented below was committed directly on top of that point and
fast-forwarded into `main`. Branches `2.5.52`, `2.5.53`, `2.5.54`, `2.5.55`,
`2.5.56`, and `main` all share the same linear ancestry.

### What shipped

**Version bump** (`432ce75`). One-liner: `templates/_nexoraVersion.html`
updated from `nexora 2.5.53` → `nexora 2.5.54`. (The label drifted by one
because the previous bump was skipped — 2.5.55 carried the 2.5.54 label in
the footer template until it was further updated in `fd36025`.)

**API_PREFIX production hotfix** (`fd36025`).

Two related fixes in `app.py`, both around timestamp handling in admin
endpoints when running behind the production reverse-proxy / FastCGI stack:

- `api_admin_logs_export` (CSV export of admin logs) — some ODBC drivers
  return `datetime2` columns as strings rather than `datetime` objects, so
  `row.Timestamp.isoformat()` raised in prod. Replaced with a normaliser
  that handles `None`, datetime objects (`isoformat()`), and string values
  (replace the first space with `T` for ISO-8601 form).
- `api_admin_user_activity` — same fix applied to per-user activity rows.

The remaining files in the diff are:

- `templates/_nexoraVersion.html` — version label updated.
- `templates/js/_headerJS.html` — small adjustment.
- `templates/js/admin/_sessionsJS.html` — small adjustment.
- `templates/js/admin/_userDetailJS.html` — 16 lines touched (likely the
  same URL-prefix concern in admin fetch calls).

> The "API_PREFIX" name in the commit message refers to nexora's
> `PrefixMiddleware` / IIS URL-rewrite setup (see `CLAUDE.md` and
> `web.config`); the underlying root cause for these specific changes is
> the ODBC datetime-as-string behaviour in production.
