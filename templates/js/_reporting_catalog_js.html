{# One fetch per read-only reporting catalog, per page load. The reporting page is five separate IIFEs (tabs, Simple, Advanced, dashboard, drill) and each of them needs the same catalogs. Because none of them can read another's state, each used to fetch its own copy: a single /reporting load asked for /api/reporting/sources three times and /api/reporting/measures three times, all identical, all serialised behind one another. This memo is the one thing they share -- not state, just the in-flight promise. Only the two immutable-per-session registries live here. /reports is deliberately NOT memoised: it changes whenever a report is saved, renamed or deleted, and a cache would need invalidating at a dozen call sites. ponytail: that leaves two /reports fetches per load; memoise it too only if it ever shows up as a real cost. #}
