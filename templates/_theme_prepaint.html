{# Sets html.dark (and .sidebar-pinned) synchronously, before first paint. Include this as the very first thing in a page's real -- right after the charset/viewport metas, before any external script/link. Why this exists separately from _header.html's own UI-prefs script (issue #155): _header.html is {% include %}'d inside every page's , but its own markup opens with a *second* ... of its own. The HTML parser folds that nested into the surrounding (a stray start tag mid-body is dropped, but the script/link/style/meta tags that were meant to live inside it still get processed -- they just end up positioned as children instead of children -- see the HTML5 tree-construction rules for "in body" handling of head-only tags). So _header.html's dark-mode script only ever runs *after* the page's real - and often the first paint that comes with it - have already happened: a visible flash of the default light theme before it flips to dark. (reporting.html's own rp-anim script already works around this same gap for the motion pref, via the same localStorage mirror read below - see its comment.) This partial duplicates just the minimal pre-paint essentials so theme/sidebar are correct from the first frame. _header.html's script still runs afterwards and re-applies the full pref set (accent, motion, density, ...) - harmless, since by then theme/sidebar already match and it's a no-op repaint. Setting the .dark class alone isn't enough to stop the flash: the rule that actually paints the dark background (html.dark's --nx-page token + body.nx-app's `background: var(--nx-page)`) lives in nexora-ui.css, which -- same root cause as above -- only reaches the page via _header.html's body-embedded , so it loads/applies later than a real stylesheet would. Between this script running and that stylesheet arriving, the browser has nothing telling it what "dark" should look like and paints its UA-default white in the meantime. So this also sets the background color directly, inline, via `style` -- no stylesheet load required for the first paint to be correct. The hex values mirror nexora-ui.css's --nx-page token; once that stylesheet loads it takes over (same color, so no visible change). #}
