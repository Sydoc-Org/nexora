{# Installable-app head tags (#354). Included by _header.html (every signed-in page) AND by the signed-out login/landing pages -- the browser only offers "Install" / "Add to Home Screen" on a page that carries these, and the login screen is exactly where somebody decides to install nexora. The manifest is a route, not a file under static/, because start_url and scope have to carry the /nexora prefix on PROD and STAGING but not on INT, and the app name carries the environment. See core.web_app_manifest(). iOS ignores most of the manifest and reads its own apple-* tags instead, so both sets are needed: - apple-touch-icon is what actually lands on an iPhone home screen. With none, iOS invents one from a screenshot or the first letter of the page title, which is what nexora looked like before this. - apple-mobile-web-app-title sets the name under the icon. Without it iOS uses , which here would read "Dashboard - nexora". - apple-mobile-web-app-capable is the old spelling of the standard mobile-web-app-capable; iOS still only honours the prefixed one, so ship both rather than picking a side. Icons are generated from the real CSS logo by scripts/make-app-icons.py -- a home screen icon cannot animate, so they are one frozen frame of it. #} <link rel="manifest" href="{{ url_for('web_app_manifest') }}"> {# theme-color tints the browser's own top strip and, in an installed app, the area behind the status bar. A single dark value left that strip navy while the page below it was light -- "the top part is stuck in darkmode" (#370). It has to follow nexora's OWN theme, not `prefers-color-scheme`: the theme is a UI pref, so somebody on a light OS can be in dark mode and vice versa, and a media-scoped pair of tags would get exactly those people wrong. `html.dark` is the single thing every theme path already agrees on -- the pre-paint scripts set it before first paint, the sidebar toggle and the Appearance panel set it after, and `theme: system` flips it when the OS does -- so the meta follows that class rather than re-deriving the theme. Both values mirror nexora-ui.css's --nx-page token. #} <meta name="theme-color" content="#0f172a"> <script nonce="{{ csp_nonce() }}"> /* Keeps the three theme-dependent things that live OUTSIDE the stylesheet in step with `html.dark`: the theme-color meta, and the inline background-color / color-scheme that the pre-paint scripts put on <html> to stop a flash of the wrong colour before the CSS lands. Those two inline styles were the real bug behind #370. They are written once, before paint, and nothing updated them afterwards -- so switching to light mode left <html> painted #0f172a while the body went light. '#0f172a' : '#f9fafb'; } if (root.style.colorScheme) { root.style.colorScheme = dark ?
